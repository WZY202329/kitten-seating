# 喵屋排排坐

100 关猫咪排序玩法版（v0.4.0）。原生 JavaScript + Canvas 2D；浏览器试玩与抖音小游戏共用规则、界面和本地存档逻辑。不需要安装 npm 依赖，不使用业务服务器或数据库。

## 本地试玩

需要 Node.js 20 或以上版本。在仓库根目录运行：

```powershell
npm run build
npm start
```

打开 [本地试玩](http://127.0.0.1:4173)。开发预览服务只用于提供静态文件，存档保存在浏览器本地。关闭服务后，下次使用同一个地址和浏览器访问仍可读取缓存；更改地址、端口或浏览器不共享进度。

也可以直接打开生成的 `dist/index.html`，但建议固定使用上述本地地址，保持存档来源一致。

开发中修改代码后重新运行 `npm run build`，再刷新页面。默认只监听本机，不自动向局域网开放。

## 怎样玩

- 打开游戏先进入主菜单，点击“开始游戏／继续游戏”进入经典排序；关卡底部可返回菜单，保留当前局面和撤回记录。
- 主菜单和游戏内都能进入设置。游戏音效、背景音乐有独立开关和 0～100% 音量条，可以点按或拖动，设置自动保存在本机。
- 点一排，选择这一排最右侧的小猫；再点目标排移动。
- 目标排必须有空位，且为空排或最右侧是同类小猫。
- 每次只移动一只。同类依靠颜色与花纹区分。
- 每个非空排都坐满同类小猫，即可通关。
- 点击“撤回”“重来”“小提示”获取免费帮助，无时间和步数限制。
- 主菜单点击“选择进度”，先选大关再选小关；10 个大关各有 10 个小关，以 `1-1` 到 `10-10` 标记。关卡标题也可打开当前大关的小关目录。
- 小关逐关解锁，已完成小关可重玩；切换时保存尚未完成的局面和撤回记录，回来可继续。未解锁大关可查看目标和漫画预告。
- 每个大关的 10 个小关全部完成后，首次显示一篇三格漫画。可跳过，后续大关照常解锁；随时在对应大关点击“阅读本章漫画”回看。
- 10 篇原创短剧情讲述四只猫一起安家的过程。前五关熟悉规则，第五关后继续第六关；第 100 关后展示最后一篇漫画，并返回进度目录自由重玩。

四只主角为橘子、灰灰、奶茶、墨墨（黑白猫）。

## 已实现

- 新启动展示完整健康游戏忠告，主菜单和游戏界面可回看8+适龄提示；8+为开发自评，平台申报与真实防沉迷验收仍待完成。
- 前五个固定教程关，保留原布局、关卡 ID 和旧存档。
- 后 95 关按固定种子进入时生成，全部有合法解；剔除交换颜色或排顺序产生的重复局面。
- 猫咪按尾巴、后肢、身体、前爪、头部分层绘制，各部分独立运动；具有错开的眨眼、呼吸、抬爪与尾巴动作。
- 移动包含约 560 毫秒的蓄力、弧线腾空、落地缓冲；前后爪收伸不同，头部与身体错位回稳。系统减少动态效果时关闭待机动作。
- 使用浅灰蓝背景与座位、较深的猫咪轮廓、体块渐变和接触阴影，增加角色与环境的分界。
- 选中与错误反馈、完成反馈。
- 免费撤回、重开确认、分片计算和可取消的一步有效提示。
- 自动保存通关记录、当前局面、切换小关前的未完成局面、撤回历史、漫画浏览状态及声音设置。
- 大关／小关选择、完成状态、继续入口与锁定提示；旧存档中已完成的大关自动解锁对应漫画。
- 三格短篇漫画，包含场景、对话、章节线索；Canvas 原生绘制，浏览器和抖音共用，无图片加载和网络依赖。
- 存档格式校验、旧关卡版本回退、损坏存档恢复和保存失败重试。
- 有长度上限的本地试玩记录，浏览器主动下载 JSON，抖音端主动复制。
- 原创合成音效与约 23 秒循环的轻柔背景音乐，两组音量和开关独立保存；首次操作后播放，切到后台暂停，回到前台按设置恢复。
- 手机窄屏和桌面预览，以及键盘可访问的辅助操作按钮。

清理缓存或更换设备会丢失本地进度。没有云备份、真实广告、线上账号系统或自动上传的分析数据。

## 抖音开发者工具导入

开发方式为原生 JavaScript + Canvas 2D，自研绘制与规则，不依赖第三方游戏引擎。

1. 运行 `npm run build`。
2. 在抖音小游戏开发者工具中导入 `dist/douyin`，填写你自己的小游戏 appid；未内置真实 appid。
3. 选择普通小游戏／JavaScript 项目，竖屏运行。
4. 在工具和真机中检查触控、安全区、存档、音效及前后台切换。

也可复制 `douyin.config.example.json` 为 `douyin.config.json`，在其中填写真实 AppID，再构建。构建会优先使用该本地配置，并保留开发者工具已写入工程配置的 AppID，不会在重新构建时清空。本地配置不会提交到仓库。

这里提供的是玩法验证构建，尚未通过抖音开发者工具和真实手机验证；当前没有侧边栏复访、真实广告或官方分析埋点。

入口与 Canvas 方案依据：[抖音小游戏开发指南](https://developer.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/dev-guide/bytedance-mini-game)。

## 关卡生成与资源开销

- 前 5 关固定，后 95 关由不可变的 v1 生成规则和固定种子复现。重开、刷新、不同设备上的同一关布局一致，设备之间仍不共享进度。
- 从完成局面进行可逆打散，保留反向还原路径，保证初始关卡有解；玩家仍可能走入死局，可以撤回或重开。
- 只在进入时生成当前局面及解题路径，选关目录读取轻量元数据，一次仅缓存一个完整关卡。
- 为了切换小关后继续，本地另存玩家已经开始、尚未完成的局面与撤回记录；没有预先生成百关局面。该存档会随实际游玩增加，受设备缓存空间限制。
- 提示优先使用已验证路径；玩家偏离该路径时采用有节点和时间预算的搜索。
- 100 关的布局 JSON 合计约 4 KB。按需生成主要用于低成本扩展和复现，并不意味着运行内存按关卡数成比例减少；提示搜索、撤回历史和绘制也占内存。
- 后段关卡增加颜色和容量，具体难度仍需真人试玩校准；不承诺每一关都比前一关更难。

运行 `npm run levels:check` 会校验所有关卡并生成 `artifacts/level-report.json`，包含局面字节数、本机生成耗时、最短解步数和提示搜索节点数。该耗时不能代替手机性能测试。

可选的浏览器验证不需要 npm 包，使用本机 Chromium：

```powershell
$env:CHROME_PATH = '你的 Chrome 或 Chromium 可执行文件绝对路径'
node scripts/browser-check.cjs
```

浏览器验证使用独立的临时测试配置，结果截图存入 `artifacts`，支持时录制 `cat-motion.webm` 以检查实际动作。它会启动临时的本机预览服务和无界面浏览器，结束时关闭自己启动的进程。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `src/core.js` | 移动、完成判定、局面校验与分片求解 |
| `src/levels.js` | 教程、百关元数据、章节与当前关卡缓存 |
| `src/generator.js` | 固定种子、可逆打散、已验证路径提示 |
| `src/motion.js` | 猫咪分部件姿态、跳跃轨迹、动作时长 |
| `src/game.js` | 游玩流程、提示、撤回及生命周期 |
| `src/storage.js` | 存档校验、读写与本地试玩记录 |
| `src/audio.js` | 两组声音的独立音量、播放解锁和前后台暂停恢复 |
| `src/story.js`、`src/comic.js` | 十篇剧情脚本、大关完成进度与三格漫画绘制 |
| `src/drawing.js`、`src/view.js` | 猫咪绘制、界面与点击区域 |
| `src/browser.js`、`src/douyin.js` | 浏览器／抖音平台适配 |
| `scripts` | 构建、本地预览、语法及浏览器检查 |
| `tests` | 核心行为与原生构建测试 |

美术为项目内 Canvas 绘制，音效与背景音乐由 `scripts/audio-assets.cjs` 在构建时原创合成，两端使用相同的本地 WAV 资源。没有外链素材、字体、音乐或 CDN 依赖。抖音音频适配参考[官方音频指南](https://partner.open-douyin.com/docs/resource/zh-CN/mini-game/develop/guide/basic-function/audio)，仍需在开发者工具和真机检查系统静音与音频生命周期。
